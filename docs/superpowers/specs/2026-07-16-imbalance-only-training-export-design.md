# Imbalance-only training export design

## Goal

Make the existing imbalance-only predictor trainable from the official Elia historical
minute series, without adding load, wind, solar, or weather data in this iteration.
The resulting model bundle must use the same causal feature contract as the live
predictor and must be promoted only after the existing chronological evaluation gates
pass.

## Data sources

- ODS133 is the historical source for training. It contains one-minute imbalance
  observations and associated ACE, quality, and imbalance-price fields from the MARI
  local go-live onward.
- ODS161 remains the near-real-time source for the running pipeline and dashboard.
- Historical backfill must select ODS133 explicitly; the current bounded backfill path
  must not accidentally request ODS161 for a historical range.

## Architecture

The flow is:

```text
ODS133 -> historical backfill -> NATS/ClickHouse imbalance observations
       -> point-in-time feature replay -> TrainingExample labels
       -> checksummed NPZ training dataset -> existing trainer
       -> candidate bundle -> manual promotion -> predictor runtime
```

The exporter will reuse `FeatureEngine`, `FeatureReplaySession`,
`build_training_examples`, and `write_training_dataset`; it will not duplicate feature
engineering or model-label logic. Only canonical system-imbalance observations are
queried. The existing context feature columns remain present and masked according to
the imbalance-only registry, preserving the model input contract.

## CLI and workflow

Add an `imbalance-export-training` command accepting explicit UTC `--start`, `--end`,
and `--output` arguments. The command validates the range, opens one reusable replay
session, builds snapshots in bounded batches, creates next-minute/auxiliary/flip labels,
and writes an immutable checksummed dataset. It fails on empty ranges, insufficient
history for the 180-minute context window, non-monotonic timestamps, or schema drift.

Expose the same flow through a Make target:

```bash
make backfill START=... END=...
make export-training START=... END=... OUTPUT=...
make train DATASET=... OUTPUT=...
```

Promotion remains an explicit operator action through `promote_bundle`; the exporter
and trainer never replace `models/production` automatically.

## Point-in-time and labels

Feature snapshots use observations at or before each cutoff and the existing causal
history replay. The next-minute target and flip labels are generated by the existing
training-data functions. No target timestamp or future observation may enter a feature
snapshot. Final observations missing a next-minute target are skipped, while missing
auxiliary horizons retain their masks.

## Error handling

- Historical source selection is explicit and covered by tests.
- HTTP/backfill failures remain retryable at the ingestor layer.
- Export failures leave no partial output directory.
- Existing dataset checksums and metadata remain the integrity boundary.
- Candidate validation and promotion gates remain unchanged.

## Verification

Add unit tests for historical dataset selection, exporter range validation, replay
reuse/batching, no-future leakage, label creation, empty-output cleanup, and Make/CLI
argument handling. Run the existing unit suite plus lint, type checking, and a small
ClickHouse-backed export smoke test.
